# L3 · 能力提升

## 定位

**学完就能做基础的数字 IC 设计工作。** 内容更专业、更全面，实践项目包含**对接工作**。

到了这一级，重点已经不是"写 Verilog"了——L2 结束时你**会写**了。L3 补的是**会写 RTL 和能承担设计任务之间的差距**：设计流程、时序约束、检查工具、验证方法学、交付规范，以及**怎么和上下游团队配合**。

## 适合谁

- 已经能独立写可综合 RTL（或已完成 L2）
- 目标是入职数字 IC 设计岗 / 转岗 / 在现有岗位上承担实际设计任务
- 需要从"自己写代码"过渡到"在团队里交付模块"

## ⚠️ 先说清楚本仓库的工具限制

**这一点很重要，不能含糊。** 仓库自带的只有 **iverilog + GTKWave**（其余按需装，见下），它不是工业设计工具链：

| 内容 | 本仓库能做到 | 做不到 |
|---|---|---|
| RTL 功能设计 | ✅ 完整（iverilog 仿真 + 自动判定） | — |
| 测试台与验证 | ✅ 完整（自检测试台、随机激励、覆盖率概念） | UVM 类库、商业仿真器特性；代码覆盖率需装 verilator |
| 逻辑综合 | ⚠️ 装 **yosys** 能真综合、看门数、比状态编码；**零下载**的 iverilog `-t blif`（门级网表）/ `-t sizer`（FF 与门数估算）也能出真实数字。⚠️ 实测：OSS CAD Suite 的 yosys 分组件装完**跑不起来**（见下），所以「装了 yosys」目前不等于能综合 | ❌ 跑不了 DC / Genus，没有工艺库，面积/时序不是真实数字 |
| 静态时序分析 | ⚠️ 只能讲原理 + 手算 slack + 读真实报告样例 | ❌ **Windows 原生无方案**（OpenSTA 需 WSL2）。没有真实 slack |
| Lint / CDC 检查 | ⚠️ 自带 `_lint.py` 只覆盖锁存器；装 **verilator** 可补真 lint（位宽/组合环/多驱动）；装 **verible** 可补编码规范检查 | ❌ CDC 没有成熟开源工具，只能人工审查 + 形式验证辅助 |
| 形式验证 | ⚠️ 装 OSS CAD Suite 的 **sby / eqy / z3** 可做属性验证与等价性检查 | ❌ 规模和易用性远不如商业工具 |
| DFT / 低功耗 | ⚠️ 只能讲概念和接口 | ❌ **Windows 原生无方案**。且 L3-14 / L3-13 大纲本来就没承诺动手 |

**装不装由你定，缺工具不阻塞开课。** 跑 `python tools/check_tools.py --level L3` 看这一级缺什么、缺了会怎样、装什么能补，然后 `python tools/setup_tools.py --install <id> --lock` 装到仓库里（不影响系统环境）。

**注意 `verilator` 分两条路，成本差很多**：`--lint-only` 装完即用；`--binary`（真正编译仿真模型，覆盖率、并发断言靠它）需要 C++ 编译器 + `make`。别把「装了 verilator」当成「断言能跑了」。

⚠️ **纠一个容易想当然的地方：这条链的瓶颈是编译器，不是 make。** 实测过了——make 那步可以用 `mingw32-make` 顶替（verilator 认 `MAKE` 环境变量），但本机唯一的 g++ 是 Qt 自带的 mingw 7.3（2017 年），而这个 verilator 是按 **GCC 15.2.1** 配置的，之后连撞四个坑：`-fcf-protection=none` 不认（GCC 8+ 才有）、`verilated.mk` 里 `python3` 找不到、`GetProcessMemoryInfo` 缺 `-lpsapi`、最后链接报 `WinMain` 未定义。逐个绕过去也不牢靠。**结论：要打通得换现代 mingw-w64（`mingw` 条目，约 250 MB），补一个 make 解决不了问题。**

⚠️ **OSS CAD Suite 的分组件 Windows 资产不自包含**，这一条影响 L3 好几项能力。`windows-x64-yosys.tgz` 装完，`yosys.exe` 启动即 `STATUS_DLL_NOT_FOUND`——它要 `libgcc_s_seh-1 / libwinpthread-1 / libstdc++-6 / libffi-8 / libreadline8 / tcl86 / zlib1` 一整组运行时 DLL，而组件里一个都不带，Python 的 `python3` 组件也不带。表现是**一个字节输出都没有、也没有报错信息**，只看「文件在不在」必然误判成装好了。`check_tools.py` 现在会把它显示成 `⚠ 已安装但不可用`，理由写清楚。**形式验证那几项（sby / eqy / z3）依赖同一套运行时，很可能同样情况，本仓库尚未实测**——装之前先按这个预期降低期待。

**所以 L3 的教法会明确区分两类内容**：

- **能动手验证的**：RTL 设计、功能验证、协议实现、CDC 的行为验证，以及装了工具之后的综合、lint、形式验证 → 照常在仓库里写代码跑判定
- **只能讲 + 读 + 手算的**：STA、DFT、低功耗、CDC 静态检查 → 讲清楚原理、给出真实报告样例读解、手算 slack，并在 `progress/notes/` 里留下笔记。**这些内容的检验方式是想明白、说清楚，不是跑通。**

**L3-18 的 SVA 已按实测改写**，不再指望装工具解决。可用的部分比想象中多，不能用的那部分也有确定的替代（实测结论）：

| 写法 | iverilog 实测结果 |
|---|---|
| `assert property` + `property` / `\|->` | ❌ 语法错误（iverilog，带 `-g2012` 也是）；verilator 只覆盖子集，且要编译出模型才跑得起来，而那条链卡在编译器上（见上） |
| **立即断言** `assert (expr) else $error(...)` | ✅ 可用（`sim.py` 本来就传 `-g2012`），但 `$error` **不改变判定结果**，只打印 |
| `$fatal` | ⚠️ 能停仿真且 `vvp` 退出码为 1，但会在 `TEST_DONE` 之前中断 → `sim.py` 判成 **`inconclusive`**（"没有收尾标记"），不是 `fail` |
| **独立 `always` 块当并发断言，用 `VLEARN_CHECK` 上报** | ✅ 走仓库现成的判定协议，给出**带用例名和时间点的逐条 pass/fail**——这才是本仓库里"写断言"的正确姿势 |

所以这一讲教的是**断言的思想**（前置条件、时序蕴含、`disable iff` 式的豁免窗口），实现手段是手写检查块，判定走仓库协议。学不到的是 SVA 的语法本身——这一点会明说，不含糊。

不含糊其辞是这一级的基本要求——**知道某个东西自己没真正验证过，比假装验证过强得多**。

## 学完的检验标准

1. 拿到一份规格，能独立完成微架构设计并说明取舍理由
2. 写完 RTL 后能自己判断：综合出来大概多大、关键路径在哪、有没有 CDC 风险
3. 能读懂综合报告和时序报告，知道违例该从 RTL 还是约束上修
4. 能写出让验证工程师和软件工程师**看得懂、用得上**的交付文档
5. 能参与 code review，提得出有依据的意见，也接得住别人对自己代码的意见
6. **清楚知道自己哪些结论是验证过的、哪些是推导出来的** —— 这条最重要

## 学完去哪

去做真实项目。这一级之后，本仓库能提供的系统性内容就到头了——剩下的靠实际项目。如果后续需要补，可以按需回到 `progress/notes/` 里补专题。

## 级别内的摸底

L3 摸底重点在**真实设计经验**和**流程认知**：

- 独立设计过模块吗？从规格到 RTL 完整走过一遍？
- 知道综合是怎么做的吗？见过综合报告或时序报告吗？
- 知道 setup / hold 违例的区别吗？会算 slack 吗？
- 跨时钟域有哪些处理方式？
- 参与过 code review 吗？给别人的 RTL 提过意见吗？
- 和验证/后端/测试团队打过交道吗？

按摸底结果跳模块。如果技术很扎实、只缺流程和对接认知，可以只做模块 A 的后半 + 模块 D + 模块 E 的 L3-40。
