# 课程总览：三级分层

> **本仓库的教程分三个级别。开始学习前，第一步是选定级别。**

## 三个级别

| 级别 | 名称 | 一句话定位 | 学完能干什么 |
|---|---|---|---|
| **L1** | [数电知识学习验证](L1-digital-logic.md) | 用 Verilog 把数电课本上的电路写出来验证 | 数电知识扎实，能用 Verilog 描述和验证课内电路 |
| **L2** | [基础 Verilog 学习](L2-verilog-language.md) | 全面学 Verilog，语言的各种使用场景都覆盖 | 独立完成中小规模可综合 RTL 设计，会写自检测试台 |
| **L3** | [能力提升](L3-professional.md) | 面向实际数字 IC 设计工作，含流程、约束、对接 | 能做基础的数字 IC 设计工作，能与验证/后端/DFT 团队对接 |

## 三个级别的关系

**是阶梯，不是三条平行线。** L2 建立在 L1 之上，L3 建立在 L2 之上。

但**可以从中途进入**：如果数电基础已经扎实，直接从 L2 开始；如果已经能独立写 RTL，直接从 L3 开始。允许跳级，但**不跳过摸底**——每一级内部仍然要摸底，确定从该级的第几讲切入。

```
L1 数电验证 ──→ L2 基础 Verilog ──→ L3 能力提升
   │                │                   │
   └── 只覆盖数电范围 └── 覆盖语言全貌    └── 覆盖工作流程
       刻意限制语法      主动扩语法        超出语言本身
```

三级的**区别不在于难度递增这么简单，而在于覆盖范围的扩张**：

- **L1 刻意做减法**：只用数电范围够用的那一小撮语法（`wire/reg`、`assign`、`always @(*)`、`always @(posedge clk)`），不碰 `generate`、参数化、函数任务、文件 I/O。目的是让注意力落在**电路本身**，而不是语言特性上。
- **L2 全面铺开**：语言的各个使用场景都涉及到，包括不可综合但仿真验证要用的部分（时序控制、文件 I/O、随机化）。
- **L3 走出语言**：设计流程、时序约束、lint/CDC、低功耗、DFT、验证方法学，以及**对接工作**——这部分已经不是"写 Verilog"了。

## 第一次交互：先选级别

**每次新开始学习时，第一件事是让用户选级别。** 不要替用户决定，也不要默认从 L1 开始。

选择时给的信息要够判断，参考这张表：

| 你的情况 | 建议 |
|---|---|
| 数电正在学或刚学完；Verilog 没碰过；想先把数电搞扎实 | **L1** |
| 数电基础没问题；想系统学会 Verilog 这门语言；目标是能独立写 RTL | **L2** |
| 已经能独立写可综合 RTL；目标是入职 / 转岗 / 承担实际设计任务 | **L3** |
| 不确定 | 说清楚三个级别的工作量差别，让对方挑；或从 L1 摸底，按摸底结果往上跳 |

**允许中途升级**：学到一半发现太浅，随时可以跳到下一级。跳级时把已完成的讲次在 `progress/` 里标注清楚，避免重复学。

## 选定之后：摸底

选完级别**不等于**直接开讲。每一级内部仍要做一次**自适应摸底**，确定从该级的第几讲切入：

- L1 摸底：数电概念 + 能否把真值表翻译成 Verilog
- L2 摸底：Verilog 语法覆盖面 + 对可综合语义的理解（尤其阻塞/非阻塞）
- L3 摸底：是否真独立设计过模块 + 对设计流程（综合/时序/CDC）的了解程度

摸底同样是**允许说"不会"**——它的作用是定位，不是考核。摸底结果写进 `progress/log/`。

## 全局节奏

不管哪一级，每一讲的节奏是一样的：

1. **讲概念** —— 落点在"这行代码对应什么硬件"
2. **给练习** —— 先自己写，卡住给提示，不直接给答案
3. **跑判定** —— `python tools/sim.py ...`，测试台说了算
4. **看波形 / 结构图** —— 结果和预期不符时，`tools/viz.py` 出波形和结构图对照看
5. **记进度** —— 写进 `progress/log/`，踩过的坑写进 `progress/notes/`

编号约定：讲次编号带级别前缀，`exercises/` `tests/` `solutions/` 三处对齐。

```
exercises/L1-05/README.md          题组说明
exercises/L1-05/decoder3_8.v       作答
tests/L1-05/tb_decoder3_8.v        测试台，顶层固定 tb_decoder3_8
solutions/L1-05/README.md          解答说明
solutions/L1-05/decoder3_8.v       参考答案
```

## 每讲的题目怎么出

**每讲出一组题，不是一道题。** 详细规范见 [`exercises/README.md`](../exercises/README.md) 和 [`solutions/README.md`](../solutions/README.md)。

| 层次 | 数量 | 作用 |
|---|---|---|
| 基础题 | 1-2 | 对应本讲知识点的最小形态 |
| **变式题** | **3-6** | **同一知识点换场景**——有效电平、位宽扩展、编码方式、时序约定、接口约定、边界情形、写法差异。**这一层是"覆盖各种场景"的主力** |
| 应用题 | 1-2 | 用到真实/组合场景 |
| 调试题 | 1 | 给有 bug 的代码，找出来并修 |
| **综合题** | 见下 | 跨知识点整合 |

**综合题的位置是固定的**：

- **每章末尾 1 道** —— 跨本章几讲。例：组合逻辑章末做"数值比较显示电路"（译码器 + MUX + 比较器）。
- **每级末尾 1-2 道大题** —— 跨整级。已在各级大纲里标出：L1 是数字钟 + 密码锁，L2 是 FIFO / UART / APB，L3 是完整交付演练。

综合题**不讲新语法**，只考"学过的东西怎么组合"；测试台**分别验证子模块和整体**。

> 为什么这么安排：一个知识点只在一种场景下练过等于没掌握。3-8 译码器会写了，换成低有效输出就卡住、换成双使能就卡住——**那些"换个说法"的场景才是真正要覆盖的**。而综合题负责把散在各讲的知识点收口成解决实际问题的能力。
