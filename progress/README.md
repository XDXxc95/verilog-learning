| 子目录 | 放什么 | 粒度 |
|---|---|---|
| `log/` | 每次学习的记录 | 一次一个文件，`log/2026-09-24.md` |

## `log/` 记什么

一次学习记一条，模板：

```markdown
# 2026-09-24

## 级别
- 选定 L2 基础 Verilog 学习

## 做了什么
- L2 摸底
- 讲了阻塞/非阻塞赋值的区别

## 结果
- 摸底结论：可综合语义清楚，但没用过 generate / 文件 I/O
- 跳过第一章，从 L2-15 开始

## 卡在哪
- `case` 缺 `default` 会推断锁存器，这个反直觉，需要再练

## 下次
- L2-24 generate 参数化
```

**「级别」这栏第一次记录时必须写**，它是后续所有教学的依据——L1 和 L2 的覆盖范围差别很大，级别搞错了整个课程就偏了。

**「卡在哪」这栏最重要**——它是下一讲要不要复习的依据，也是难度校准的输入。**「结果」里的摸底结论**决定从第几讲切入，也要写清楚。

## `notes/` 记什么

**踩过的坑**优先，其次才是概念总结。一条好笔记长这样：

```markdown
# 组合逻辑缺分支会推断出锁存器

## 现象
case 语句没写 default，仿真跑得完全正常，行为也对。

## 为什么错
仿真里不赋值 = 保持原值，看起来像"没变"；
综合时"保持原值"只能靠一个存储元件实现 → 综合器给你插一个锁存器。
组合逻辑里出现锁存器，时序分析会很难做，通常不是你想要的。

## 怎么避免
- case 必须写 default
- if 必须写 else（或者保证信号在块内所有分支都被赋值）
- 跑 tools/_lint.py，它会直接报 latch_inference

## 验证
tests/_smoke/neg/latch_incomplete_case.v
```

写清楚**现象 → 原因 → 怎么避 → 怎么验证**，以后回来看一眼就能用。
