# solutions —— 参考答案

对应 `exercises/<讲号>/` 的题组，目录结构一一对应：

```
exercises/L1-05/README.md          题组说明
exercises/L1-05/decoder3_8.v       作答
solutions/L1-05/README.md          解答说明（含各题分析 + 场景对比）
solutions/L1-05/decoder3_8.v       参考答案
solutions/L1-05/artifacts/         实际运行产物（见下）
```

**题组里每道题都要有解答**，一道不落——包括调试题（要给"错在哪 + 怎么改"）和综合题（要给模块划分思路）。

---

# 每道练习都必须带实际运行产物

> **课程里的每一道练习，都要有真实跑过的结果 + 能看的波形/结构图。** 不能只给代码让人自己去跑。

产物放在 `solutions/<讲号>/artifacts/<设计名>/`：

```
run.txt          实际执行的命令行 + 判定摘要 + 完整 JSON
wave_ascii.txt   终端 ASCII 波形（纯文本，可 diff、可贴进文档）
wave.html        自包含交互波形（双击就能看）
hierarchy.svg    层次图
module_*.svg     各模块结构图
```

**为什么放 `solutions/` 而不是 `build/`**：`build/` 是 gitignore 的临时目录，run 一次就被覆盖；而这里是**课程材料的一部分**，要入库、要随模板一起走。

**一键生成**（不用手敲 `sim.py` + `viz.py`）：

```bash
python tools/lesson.py L1-05          # 生成 L1-05 全部模块的产物包
python tools/lesson.py L1-05 --open   # 生成后直接打开波形
python tools/lesson.py --list         # 看看有哪些讲、各配了几个模块
```

产物靠**文件名配对**定位：`tests/L1-05/tb_<设计名>.v` ↔ `solutions/L1-05/<设计名>.v`。名字对不上就配不上，工具会明确报出来而不是默默跳过——所以**模块名要严格遵守命名约定**。

## 产物怎么用

- **`run.txt`** 是"这道题跑出来是什么样"的**证据**。解答里写"验证结果"时，直接引用它，不要另编一份。
- **`wave_ascii.txt`** 可以直接贴进解答文档，让学员在静态阅读时也能看到时序。
- **`wave.html`** 是给人细看的，解答里链接过去即可。
- **`*.svg`** 是结构图，用来讲"这段代码综合出什么电路"——这是解答里的固定栏目，产物直接对应。

# 解答规范

> **每一份解答都不许只给代码。** 只丢一段能跑的代码 = 没写解答。

答案是**学完之后回看的东西**。学员当时为什么写错、正确的思路是怎么拐过来的、这段代码综合出来到底是什么——这些留在解答里才有复用价值。只给代码，回看时还得重新想一遍，等于白存。

## 单题解答

每道题按下面结构写：

````markdown
## 1. 3-8 译码器

### 一句话思路
用左移实现独热输出，用 en 做整体屏蔽。

### 参考答案
```verilog
assign y = en ? (8'b1 << a) : 8'b0;
```
（代码里每条**不显然**的语句都要有注释，讲"为什么这么写、综合成什么"）

### 代码分析
- **`8'b1 << a`**：移位量是变量，综合出来是桶形移位网络，等价于译码器。
  位宽写 `8'b1` 而不是 `1`——`1 << a` 会先得到 32 位中间值再截断，换个位宽组合就错。
- **`en ? ... : 8'b0`**：三元运算符综合成 2 选 1 选择器。**给了确定的默认值**，
  所以不会推断出锁存器。
- **为什么用 `assign` 而不是 `always @(*)`**：纯组合逻辑，一行表达式能说清的事，
  用 `assign` 意图更明确，也不存在漏分支的风险。

### 综合出来是什么电路
（从可综合视角讲：会变成什么硬件。可配 `tools/viz.py --schematic` 的结构图）

### 常见错误
| 错误写法 | 现象 | 为什么错 | 后果 |
|---|---|---|---|
| `case` 漏 `default` | 仿真完全正常 | 有不被赋值的路径 → 需要保持原值 → 只能靠存储元件 | 综合出锁存器，`_lint.py` 报 `latch_inference` |
| `assign y = 8'b1 << a;` 不带 en | 使能失效 | 漏了需求 | 使能用例失败 |
````

## 调试题的解答

要写清三件事：**错在哪一行 → 为什么这是错的 → 怎么修**（给出正确版本）。

不要只贴正确答案，**要说清这个错误在实际工作中会造成什么后果**——比如漏 `default` 在仿真里完全看不出来，到综合才暴露。

## 综合题的解答

多写两块：

1. **模块划分**：为什么这么拆分，接口怎么定，有没有别的拆法，各有什么取舍
2. **整体怎么验证**：子模块验证 + 整体验证的关系

# 题组小结（重要）

**每讲解答的最后，要有一节"场景对比"**——这是"练习题覆盖各种场景"这个设计真正产生价值的地方：

````markdown
# 本讲场景对比

| 题 | 场景变化 | 代码上改了什么 | 关键点 |
|---|---|---|---|
| 1 | 基础形态 | — | 移位 vs case 两种写法 |
| 2 | 输出低有效 | 加 `~` 或改成取反赋值 | 只改一行，但接口约定变了要同步改测试台 |
| 3 | 双使能 | 使能条件变成 `en1 & ~en2` | 实际器件（74LS138）的常见封装 |
| 4 | 4-16 级联 | 两个 3-8 + 高层选择 | 位宽扩展的通用套路：**高位选片子，低位选位置** |
| 5 | 实现任意逻辑函数 | 从"输出独热"变成"输出最小项之或" | 译码器的**本质用途**：它就是最小项发生器 |
| 6 | 调试 | 漏 default | 仿真看不出来，综合才暴露 |

**一句话总结**：3-8 译码器的核心是"把输入变成最小项"，单热输出只是它最直观的表现；
换成低有效、双使能、级联，变的都是**外围约定**，内核没变。
````

这一节比单题解答更有价值——它把散在各题里的"换个说法"收成一条线，学员看完才知道**自己练的其实是同一件事的不同马甲**。

# 硬性要求

1. **代码必须实际跑过**，`验证结果` 贴真实输出，不许编。
2. **每条不显然的语句都要有注释**，讲"为什么"和"综合成什么"。反例：`assign y = en ? (8'b1 << a) : 8'b0; // 把 1 左移 a 位` ← 这是废话。
3. **常见错误要写全**：现象 → 原因 → 后果。这是单题解答里最有价值的部分。
4. **要讲综合出的电路**，不能只讲仿真行为——本仓库的立场是"可综合优先"。
5. **不省略看似显然的推导**。写解答时觉得"这步这么简单不用讲"的地方，恰恰是卡住的地方。
6. **每讲最后必须有场景对比表**，把各题的差异收成一条线。
7. 有对照价值的，用 `tools/viz.py --compare` 把**错误写法**和**正确写法**并排跑，把波形差异说清楚（阻塞/非阻塞那类题，差一拍的波形最有说服力）。

## 对照着看

```bash
python tools/viz.py --compare solutions/L1-05/decoder3_8.v exercises/L1-05/decoder3_8.v \
    --tb tests/L1-05/tb_decoder3_8.v --top decoder3_8
```

产物在 `build/viz/decoder3_8/` 下，按文件名分成两个子目录，可以左右对照看时序差异。
